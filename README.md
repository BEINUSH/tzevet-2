# ערב גיבוש 🎖️

אפליקציית משחקים מולטיפלייר לערב גיבוש (16–20 משתתפים): מסך מנחה, מסך משתתף בטלפון, ומסך הקרנה למקרן/טלוויזיה. Next.js + TypeScript + Socket.io + Prisma/SQLite.

## איך זה עובד

- **Admin** (`/admin`) - יצירת אירועים מראש: סבבים, שאלות, אפשרויות תשובה, תשובה נכונה, זמן לשאלה, ניקוד, הצבעה עצמית - הכל דרך ממשק (כולל גרירה לשינוי סדר), נשמר במסד הנתונים. אפשר גם לערוך הכל בבת אחת דרך ייצוא/ייבוא CSV שנפתח ונערך ב-Excel (ראו "עריכה מרוכזת דרך Excel" למטה) - נוח במיוחד להחלפת שמות דמו בשמות אמיתיים לאורך כל השאלות בבת אחת.
- **מנחה** (`/host`) בוחר אירוע, פותח חדר ומקבל קוד הצטרפות + QR, ושולט על כל שלב: התחלה, פתיחת/סגירת הצבעה, חשיפת תוצאות, דילוג, סיום סבב, מעבר הלאה, ניקוד, הצגת/הסתרת טבלת מובילים, הסרת משתתף, מסך סיום.
- **משתתפים** (`/join` → `/play/[code]`) נכנסים מהטלפון עם קוד, מזינים שם, ומצביעים/עונים בכל סבב. אנונימי לחלוטין כלפי שאר המשתתפים. Refresh או סגירת דפדפן בטעות לא מאבדים את המקום במשחק.
- **מסך הקרנה** (`/present/[code]`) - תצוגה נקייה בלי כפתורי שליטה, מיועדת לטלוויזיה/מקרן: QR, שמות מצטרפים, שאלה, טיימר, ספירת עונים, חשיפה דרמטית (פודיום/בר-צ'ארט), טבלת מובילים, פרסים, אפקטי קול עדינים (עם השתקה).

### 6 סוגי המשחקים

1. **מי הכי...?** - הצבעה על משתתף, בלי חשיפת מי הצביע למי.
2. **מי אמר את זה?** - שאלה עם 4 אפשרויות, ניקוד לתשובה נכונה (+בונוס מהירות קטן).
3. **טריוויה על הצוות** - אותו מנגנון עם 4 אפשרויות וניקוד.
4. **הימור צוותי** - הצבעה על אחד משני "מתמודדים", ואז המנחה מסמן ידנית מי ניצח בפועל אחרי שהאתגר בוצע; מי שהימר נכון מקבל נקודות.
5. **תשובות אנונימיות** - טקסט חופשי, נחשף אחד-אחד על ידי המנחה; שם הכותב מוצג רק במסך המנחה (moderation), לעולם לא במסכים הציבוריים.
6. **פרסי הצוות** - כמו "מי הכי" אבל נאסף לכדי "קיר פרסים" במסך הסיום הסופי.

מערכת ניקוד עם הוספה/הורדה/איפוס ידניים, וטבלת מובילים שהמנחה בוחר מתי להציג.

## דרישות

Node.js 18+.

## התקנה

```bash
npm install
cp .env.example .env   # ברירת מחדל כבר תקינה להרצה מקומית
npx prisma migrate dev
npm run db:seed        # טוען את אירוע הדמו "ערב גיבוש – צוות 2"
```

## הרצה מקומית

```bash
npm run dev
```

השרת עולה בכתובת `http://localhost:3000` (Next.js + Socket.io על אותו פורט, custom server ב-`server.ts`).

### חיבור מהטלפונים (LAN)

כדי שטלפונים יתחברו, פתחו את המנחה דרך **כתובת ה-IP המקומית** של המחשב, לא `localhost`:

- macOS: `ipconfig getifaddr en0`
- Linux: `hostname -I`
- Windows: `ipconfig`

לדוגמה: `http://192.168.1.20:3000/host`. כל המכשירים חייבים להיות על אותה רשת Wi-Fi. מסך המנחה מציג QR שמפנה אוטומטית לכתובת הנכונה (על בסיס הכתובת שממנה המנחה עצמו נכנס), כך שסריקה עובדת ישר.

## מסד הנתונים

SQLite מקומי (`prisma/dev.db`, נוצר אוטומטית). Schema מלא ב-`prisma/schema.prisma`: Event, Round, Option, Session, Participant, Vote, AnonymousAnswer, RoundResult.

פקודות שימושיות:

```bash
npx prisma studio     # דפדפן ויזואלי למסד הנתונים
npm run db:seed       # זריעה מחדש של אירוע הדמו (מוחק ויוצר מחדש לפי שם)
npx prisma migrate dev --name <שם>   # אחרי שינוי ב-schema.prisma
```

לשדרוג ל-Postgres (לדוגמה לפריסה בענן): שנו `provider` ב-`schema.prisma` ל-`postgresql` ואת `DATABASE_URL` בהתאם - שאר הקוד לא משתנה.

## יצירת ערב חדש

1. `/admin` → "אירוע חדש", תנו שם (למשל "ערב גיבוש – צוות 3").
2. בעמוד האירוע: "הוספת סבב חדש" - בחרו סוג, לחצו הוספה.
3. לחצו "עריכה" על כל סבב כדי להזין את טקסט השאלה, זמן, אפשרויות תשובה (לטריוויה/"מי אמר את זה"/הימור), האם מותר להצביע לעצמך, והאם יש ניקוד.
4. גררו סבבים (מהאייקון ⠿) כדי לשנות את סדר הערב.
5. בערב עצמו: `/host` → בחרו את האירוע → "פתיחת חדר".

### עריכה מרוכזת דרך Excel (במקום ידנית אחת-אחת)

בעמוד האירוע ב-`/admin` יש כרטיס "עריכה מרוכזת דרך קובץ CSV":

1. "הורדת CSV נוכחי" - מוריד את כל השאלות הקיימות כקובץ `.csv` שנפתח ישר ב-Excel (או Google Sheets/Numbers).
2. עריכה חופשית בטבלה - למשל Find & Replace לשם דמו אחד בשם אמיתי לאורך כל הקובץ, תיקון ניסוחים, מחיקת/הוספת שורות. עמודות: `סוג` (חייב להיות אחד מהערכים המדויקים כמו "מי הכי...?", "טריוויה" וכו' - הכי בטוח להשאיר את מה שיצא מהייצוא ולא להקליד מחדש), `כותרת`, `שאלה`, `זמן_שניות`, `הצבעה_עצמית` (כן/ריק), `ניקוד` (כן/ריק), ו-4 זוגות `אפשרות_N`/`נכונה_N` (ל"מי אמר את זה"/טריוויה/הימור צוותי - סמנו "כן" בעמודת נכונה_N של התשובה הנכונה; ב"הימור צוותי" רק אפשרות_1/אפשרות_2 עם שני שמות המתמודדים, בלי לסמן נכונה).
3. שמירה כ-CSV (לא xlsx!) וחזרה ל-`/admin/events/[id]` - "העלאת CSV מעודכן".
4. **שימו לב:** ייבוא מחליף את **כל** השאלות באירוע לפי מה שבקובץ. אם יש שגיאה בקובץ (סוג לא מזוהה, שאלה בלי תשובה נכונה וכו') - הייבוא נדחה עם הסבר מדויק לפי שורה, ושום דבר לא משתנה עד שתתקנו.

## Deployment

השרת הוא תהליך Node תמידי (custom server + Socket.io) - **לא מתאים ל-Vercel** (אין תמיכה ב-WebSocket תמידי ב-serverless functions). לאירוע עצמו מריצים מקומית על מחשב אחד (ראו למעלה) - זו הדרך המומלצת, בלי תלות באינטרנט.

לפריסה מקוונת (למשל כדי לאפשר גישה מרחוק): כל מארח שמריץ תהליך Node ארוך-טווח (Render, Railway, Fly.io, VPS) עובד:

```bash
npm run build
npm start
```

הערות לפריסה בענן:
- החליפו את `DATABASE_URL` ל-Postgres (ראו סעיף מסד הנתונים) - SQLite לא מתאים לאחסון persistent על רוב פלטפורמות ה-containers האפמריות.
- ודאו שהפלטפורמה תומכת ב-WebSocket תמידי (לא HTTP-only serverless).
- הגדירו `PORT` לפי מה שהפלטפורמה דורשת.

## מבנה הפרויקט

```

src/lib/results.ts      חישוב תוצאות + ניקוד לכל סוג משחק
src/types/game.ts       טיפוסים משותפים client/server
src/app/admin/          Admin CMS - CRUD + drag&drop (Server Actions, Prisma ישירות)
src/app/                שאר העמודים: /, /join, /play/[code], /host, /host/[code], /present/[code]
src/components/         רכיבי UI משותפים (כרטיסים, טאלי, פודיום, לוח מובילים, שאלות לפי סוג...)
```

## State Machine

```
Session:  LOBBY → IN_ROUND → FINAL_AWARDS → ENDED
Round:    IDLE → VOTING_OPEN → VOTING_CLOSED → REVEALED → DONE   (או דילוג ישיר ל-DONE)
```

כל טרנזיציה מאומתת ומבוצעת בצד שרת בלבד (לא בצד קליינט), עם מנעול (mutex) לכל חדר כדי שכפל-קליק לא יגרום לכפל-מעבר. הצבעה כפולה נמנעת ברמת ה-DB (unique constraint על שחקן+סבב), לא רק ב-UI.

## אמינות - מה נבדק בפועל

הרצתי QA מלא בדפדפן אמיתי (Playwright, לא רק ברמת פרוטוקול), כולל תרחיש מקצה לקצה של Host creates room → Participants join → Lobby → Start → כל 6 סוגי המשחקים (הצבעה, סגירה, חשיפה, "מי אמר את זה" עם ניקוד, הימור עם סימון מנצח ידני, תשובות אנונימיות עם moderation) → טבלת מובילים → מסך פרסים סופי → סיום, ללא שגיאת קונסול/עמוד אחת. וגם, בנפרד, תרחישי אמינות ממוקדים:

- **Refresh/reconnect** - למשתתף וגם למנחה, כולל אחרי ניתוק אמיתי של הסוקט (לא רק רענון) - חוזרים בדיוק לאותו מקום, כולל אם כבר הצביעו בסבב הנוכחי.
- **הצבעה כפולה** - מאותו משתתף, גם דרך שני קליקים וגם דרך socket שנשלח פעמיים - נספרת פעם אחת בלבד (מאולץ ב-DB, לא רק ב-UI).
- **שני קליקים על "הבא"** - בו-זמנית ממש (לא רק ברצף) - מתקדם סבב אחד בדיוק, לא שניים.
- **הצבעה אחרי סגירת השאלה** - נדחית עם שגיאה ברורה.
- **משתתף שהוסר** - לא יכול להצביע גם אם ניסה (מאומת בשרת, לא רק שהאפשרות נעלמת מה-UI), ורואה מסך "הוסרת מהחדר".
- **ניתוק אמצע הצבעה** - מונים רק שחקנים מחוברים, כך שסבב לא נתקע ממתין למישהו שהתנתק.
- **ייצוא/ייבוא CSV** - הורדה, שינוי שם לאורך כל השאלות (כולל בתוך "הימור צוותי" ו"טריוויה"), העלאה חזרה - נבדק שהשינוי משתקף נכון ב-DB, שדגל "תשובה נכונה" נשאר צמוד לאפשרות הנכונה גם אחרי שינוי שם, וש-CSV פגום נדחה עם שגיאה מדויקת לפי שורה בלי לגעת בתוכן הקיים.

בדרך נמצאו ותוקנו שלושה באגים אמיתיים: state לא-תקין (`Cannot call startTransition while rendering`) בגרירת סדר סבבים ב-Admin, משתתף שהוסר שיכול היה עדיין להצביע, וולידציה שגויה בייבוא CSV שדרשה "תשובה נכונה" גם עבור "הימור צוותי" (שם זה נקבע חי באירוע, לא מראש).

## מה עוד שווה לשקול (לא חובה לערב הקרוב)

- Rate limiting על יצירת חדרים/הצטרפות (לא נדרש ברשת LAN פרטית)
- טסטים אוטומטיים קבועים בריפו (ה-QA בוצע ידנית מול שרת חי; אין test suite שמור)
- ריבוי מנחים בו-זמנית לאותו חדר (כרגע כל socket עם ה-hostToken הנכון יכול לשלוט, וזה בכוונה כדי לתמוך ברענון/כמה מסכי בקרה)
