# ערב גיבוש 🎖️

אפליקציית משחקים מולטיפלייר לערב גיבוש (16–20 משתתפים): מסך מנחה, מסך משתתף בטלפון, ומסך הקרנה למקרן/טלוויזיה. Next.js + TypeScript + Socket.io + Prisma/SQLite.

> **סטטוס: נקודת ביניים.** שלושת המסכים המרכזיים וכל 6 סוגי המשחקים עובדים מקצה לקצה מול הבק-אנד האמיתי (ראו "מה נבדק" למטה). **ממשק ה-Admin לעריכת תוכן עדיין לא קיים** - כרגע התוכן טעון רק דרך סקריפט seed. זה יתווסף בהמשך.

## איך זה עובד

- **מנחה** (`/host`) בוחר אירוע פותח חדר, מקבל קוד הצטרפות, שולט על כל שלב: התחלה, פתיחת/סגירת הצבעה, חשיפת תוצאות, דילוג, סיום סבב, מעבר הלאה, ניקוד, מסך סיום.
- **משתתפים** (`/join` → `/play/[code]`) נכנסים מהטלפון עם קוד, מזינים שם, ומצביעים/עונים בכל סבב. אנונימי לחלוטין כלפי שאר המשתתפים.
- **מסך הקרנה** (`/present/[code]`) - תצוגה נקייה בלי כפתורי שליטה, מיועדת לטלוויזיה/מקרן: QR, שמות מצטרפים, שאלה, טיימר, ספירת עונים, חשיפה דרמטית (פודיום/בר-צ'ארט), טבלת מובילים, פרסים.

### 6 סוגי המשחקים (מומשו במלואם)

1. **מי הכי...?** - הצבעה על משתתף, בלי חשיפת מי הצביע למי.
2. **מי אמר את זה?** - שאלה עם 4 אפשרויות, ניקוד לתשובה נכונה (+בונוס מהירות קטן).
3. **טריוויה על הצוות** - אותו מנגנון עם 4 אפשרויות וניקוד.
4. **הימור צוותי** - הצבעה על אחד משני "מתמודדים", ואז המנחה מסמן ידנית מי ניצח בפועל אחרי שהאתגר בוצע; מי שהימר נכון מקבל נקודות.
5. **תשובות אנונימיות** - טקסט חופשי, נחשף אחד-אחד על ידי המנחה; שם הכותב מוצג רק במסך המנחה (moderation), לעולם לא במסכים הציבוריים.
6. **פרסי הצוות** - כמו "מי הכי" אבל נאסף לכדי "קיר פרסים" במסך הסיום הסופי.

מערכת ניקוד עם הוספה/הורדה/איפוס ידניים, וטבלת מובילים שהמנחה בוחר מתי להציג.

## דרישות

Node.js 18+.

## התקנה

```bash
npm install
cp .env.example .env   # ברירת מחדל כבר תקינה להרצה מקומית
npx prisma migrate dev
npm run db:seed        # טוען את אירוע הדמו "ערב גיבוש – צוות 2"
```

## הרצה מקומית

```bash
npm run dev
```

השרת עולה בכתובת `http://localhost:3000` (Next.js + Socket.io על אותו פורט, custom server ב-`server.ts`).

### חיבור מהטלפונים (LAN)

כדי שטלפונים יתחברו, פתחו את המנחה דרך **כתובת ה-IP המקומית** של המחשב, לא `localhost`:

- macOS: `ipconfig getifaddr en0`
- Linux: `hostname -I`
- Windows: `ipconfig`

לדוגמה: `http://192.168.1.20:3000/host`. כל המכשירים חייבים להיות על אותה רשת Wi-Fi.

## מסד הנתונים

SQLite מקומי (`prisma/dev.db`, נוצר אוטומטית). Schema מלא ב-`prisma/schema.prisma`: Event, Round, Option, Session, Participant, Vote, AnonymousAnswer, RoundResult.

פקודות שימושיות:

```bash
npx prisma studio     # דפדפן ויזואלי למסד הנתונים
npm run db:seed       # זריעה מחדש של אירוע הדמו (מוחק ויוצר מחדש לפי שם)
npx prisma migrate dev --name <שם>   # אחרי שינוי ב-schema.prisma
```

לשדרוג ל-Postgres בעתיד (לדוגמה לפריסה בענן): שנו `provider` ב-`schema.prisma` ל-`postgresql` ואת `DATABASE_URL` בהתאם - שאר הקוד לא משתנה.

## Environment Variables

| משתנה | ברירת מחדל | הסבר |
|---|---|---|
| `DATABASE_URL` | `file:./dev.db` | חיבור למסד הנתונים |
| `PORT` | `3000` | פורט השרת |

## יצירת ערב חדש

עד שממשק ה-Admin יהיה מוכן, אירוע חדש/עריכת שאלות נעשה דרך `prisma/seed.ts` (ערכו את המערכים שם) או ישירות דרך `npx prisma studio`.

## Deployment

השרת הוא תהליך Node תמידי (custom server + Socket.io) - **לא מתאים ל-Vercel** (אין תמיכה ב-WebSocket תמידי ב-serverless functions). לאירוע עצמו מריצים מקומית על מחשב אחד (ראו למעלה). לפריסה מקוונת: כל מארח שמריץ תהליך Node ארוך-טווח (Render, Railway, Fly.io, VPS) עובד עם:

```bash
npm run build
npm start
```

## מבנה הפרויקט

```
prisma/            schema, migrations, seed
server.ts          custom Node server: Next.js handler + Socket.io
src/lib/realtime/  מנוע ה-state machine וכל אירועי ה-Socket.io
src/lib/results.ts חישוב תוצאות + ניקוד לכל סוג משחק
src/types/game.ts  טיפוסים משותפים client/server
src/app/           העמודים: /, /join, /play/[code], /host, /host/[code], /present/[code]
src/components/    רכיבי UI משותפים (כרטיסים, טאלי, פודיום, לוח מובילים...)
```

## מה נבדק (checkpoint QA)

הרצתי תרחיש מלא מול שרת חי + מסד נתונים אמיתי (לא רק unit tests): יצירת חדר, הצטרפות/הסרת משתתפים, כל 6 סוגי המשחקים ברצף (כולל ניקוד בפועל שנכתב ל-DB), הצבעה כפולה מאותו משתתף (לא נספרת פעמיים), חשיפת הימור צוותי + סימון מנצח ידני, תשובות אנונימיות + moderation, טבלת מובילים, מסך סיום עם קיר פרסים, וניסיון להתחיל משחק שכבר הסתיים (נדחה כראוי). ה-state machine (skip/next/reveal) נבדק גם ב-10 סבבים רצופים ישירות מול ה-DB - ללא תקלה.

**עדיין לא נבדק בדפדפן אמיתי** (רק ברמת הפרוטוקול/סוקטים) - מומלץ Round אחד מלא בדפדפן לפני האירוע.
